# 场馆预约与球员约战 SaaS 系统开发文档

## 1. 产品定位

本系统定位为面向球馆/体育场馆的 SaaS 管理系统，同时提供微信小程序给球员完成订场、约战、支付、核销和退款等操作。

系统同时服务三类用户：

- 球员用户：查找场馆、预约场地、发起约战、加入约战、支付、退款、查看订单。
- 场馆商家：入驻平台、管理场地、配置价格、处理预约、核销到场、查看经营数据。
- 平台运营方：审核场馆、配置佣金、管理订单、处理退款、查看结算和平台经营数据。

## 2. 技术选型

后端：

- Java 21
- Spring Boot 3.x
- Spring Security
- Spring Validation
- Spring Data JPA 或 MyBatis Plus
- PostgreSQL
- Redis
- Maven

前端：

- 微信原生小程序
- 管理后台：Vue 3 + Element Plus

基础设施：

- Linux 服务器
- Docker / Docker Compose，优先用于隔离部署
- 正式支付优先采用微信支付服务商模式，MVP 可使用平台普通商户过渡
- 对象存储用于场馆图片、资质图片和用户上传文件

## 3. 服务器约束

当前测试/部署服务器：

```text
服务器：1.69.143.156
SSH 端口：2218
SSH 用户：frank
限制：没有 80 端口和 443 端口
要求：不得影响该服务器上的其他产品
```

部署要求：

- 不使用 80 和 443 端口。
- 不复用其他产品目录。
- 不复用其他产品进程名。
- 不复用其他产品数据库名。
- 不复用其他产品 Redis key 前缀。
- 不覆盖服务器已有 Nginx、PM2、Docker、systemd 配置。
- 部署前必须检查端口占用。
- 线上端口使用高位端口，建议从 `18200` 开始规划。

建议端口：

```text
后端 API：18200，仅用于测试环境或内网代理入口
管理后台：18201，仅用于测试环境或内网代理入口
PostgreSQL：容器内部访问，不暴露公网
Redis：容器内部访问，不暴露公网
```

小程序正式上线约束：

- 当前服务器可作为后端运行机，但不能直接作为微信小程序正式接口入口。
- 正式版小程序需要配置备案域名和 HTTPS 入口。
- 仅申请域名不等于完成上线条件，还需要备案、HTTPS 证书、小程序合法域名配置和公网 HTTPS 回调地址。
- 微信支付回调、退款回调、分账回调也需要公网可访问的 HTTPS 地址。
- 如果 `1.69.143.156` 无法提供 443 端口，必须增加 HTTPS 网关、API 网关、云托管、负载均衡或另一台代理服务器。
- 推荐结构：`https://api.xxx.com:443 -> HTTPS 网关/代理 -> http://1.69.143.156:18200`。
- 证书申请可优先使用 DNS 校验方式，避免依赖当前服务器 80 端口。
- 小程序代码中不得直接请求 `http://1.69.143.156:18200` 作为正式环境地址。

## 4. 核心业务模块

### 4.1 用户模块

功能：

- 微信小程序登录
- 手机号绑定
- 用户资料
- 球员等级
- 用户状态管理
- 黑名单/风控标记

核心角色：

- 平台管理员
- 场馆管理员
- 场馆员工
- 教练
- 普通球员

### 4.2 场馆入驻模块

功能：

- 场馆申请入驻
- 营业执照/资质上传
- 联系人信息
- 场馆地址与定位
- 场馆审核
- 场馆启用/停用
- 收款商户配置

入驻状态：

```text
草稿
待审核
审核通过
审核驳回
已停用
```

### 4.3 场地管理模块

功能：

- 场地新增/编辑/停用
- 场地类型：羽毛球、篮球、网球、足球、乒乓球等
- 室内/室外
- 场地标签
- 场地开放时间
- 场地维护时间
- 场地临时关闭

### 4.4 价格日历模块

功能：

- 工作日价格
- 周末价格
- 节假日价格
- 高峰/低峰价格
- 特殊日期价格
- 按时间段配置价格
- 按场地配置价格

价格计算必须由后端完成，小程序只展示结果，不参与最终价格判定。

### 4.5 预约订单模块

功能：

- 查看可预约时间
- 临时锁定场地
- 创建预约订单
- 微信支付
- 支付成功确认预约
- 到场核销
- 取消预约
- 退款
- 订单评价，后续版本实现

预约订单状态：

```text
待支付
已预约
已核销
已完成
已取消
退款中
部分退款
已退款
支付超时
```

说明：

- 预约订单不设置独立的“已支付”业务状态。
- 支付结果由 `payment_order` 记录，例如 `待支付`、`支付成功`、`支付失败`、`已关闭`。
- 支付成功后，业务订单直接流转为 `已预约`。

### 4.6 约战模块

功能：

- 创建公开约战
- 创建私密约战
- 设置人数、费用分摊方式、球员等级要求
- 加入约战
- 退出约战
- 人满后停止加入
- 约战成员报名管理
- P1：成员 AA 支付
- P1：未成局自动退款

MVP 约战状态：

```text
招募中
人数已满
已开打
已结束
已取消
```

P1 约战状态：

```text
已成局
未成局取消
```

费用模式：

```text
发起人全额支付
成员 AA 支付
发起人预付定金，成员补齐
```

MVP 优先实现：

```text
发起人全额支付或定金支付锁定场地
发起人创建公开约战并邀请成员加入
成员加入后记录参与关系
```

二期实现：

```text
成员 AA 支付
最低人数成局
未成局自动退款
```

说明：

- 约战不能长期依赖 5-10 分钟 Redis 临时锁占用场地。
- MVP 中，约战绑定一笔已经支付成功的预约订单，AA 分摊只作为二期能力。

### 4.7 支付模块

支付方式：

- 微信小程序支付

推荐支付架构：

- 正式方案：微信支付服务商模式，场馆作为特约商户，平台通过分账收取佣金或技术服务费。
- MVP 过渡方案：平台普通商户先统一收款，系统记录场馆应结算金额，后续人工或周期结算。
- 过渡方案必须标记账务归属和合规风险，不能长期替代服务商模式。

支付流程：

```text
创建业务订单
锁定场地
创建微信支付单
用户完成支付
接收微信支付回调
校验回调签名
更新支付单状态
确认预约或约战名额
生成分账/结算记录
```

支付模块必须具备幂等能力，微信回调可能重复到达。

### 4.8 退款模块

退款规则按场馆配置：

```text
开场前 24 小时可全额退款
开场前 2 小时可部分退款
开场前 2 小时内不可退款
场馆原因可全额退款
P1：约战 AA 分摊未成局时，成员分摊款自动退款
```

退款流程：

```text
用户申请退款
校验退款规则
生成退款单
调用微信退款
接收退款回调
更新退款状态
按退款类型决定是否释放场地或约战名额
更新订单状态
```

说明：

- 未开始且全额退款成功，才释放场地时间槽。
- 部分退款、已核销订单退款、已完成订单售后退款不释放场地。

### 4.9 分账与结算模块

功能：

- 平台佣金规则
- 场馆结算账单
- 分账记录
- 退款冲正
- 对账报表
- 异常账单处理

佣金模式：

```text
按比例抽佣
固定金额服务费
比例 + 固定金额
指定场馆免佣期
```

### 4.10 通知模块

通知渠道：

- 微信小程序订阅消息
- 管理后台站内通知
- 短信，后续版本可选

通知场景：

- 支付成功
- 预约成功
- 约战加入提醒
- 约战满员提醒
- P1：约战成局
- 约战取消
- 退款成功
- 开场提醒
- 场馆审核结果

## 7. 开发规范

后端包结构建议：

```text
com.ballsaas
  common
  config
  security
  tenant
  user
  venue
  court
  pricing
  booking
  match
  payment
  refund
  settlement
  notification
  audit
  admin
```

通用要求：

- 所有金额使用整数分存储，不使用浮点数。
- 所有业务时间统一存储为带时区的时间，展示时转换为本地时间。
- MVP 预约时间槽统一按 30 分钟粒度拆分，一笔订单可占用多个连续时间槽。
- 所有核心表保留创建时间、更新时间、创建人、更新人。
- 多租户数据必须带 `tenant_id` 或 `venue_id`。
- 支付、退款、回调、分账必须有独立流水表。
- 正式支付优先采用微信支付服务商模式；如果前期资质未就绪，可使用平台普通商户收款作为过渡方案，但必须单独标记账务归属和合规风险。
- 核心状态变更必须记录日志。
- 外部回调接口必须验签。
- 定时任务必须支持幂等重试。

## 9. 本地构建与环境说明

当前开发机系统默认 Java 为 8，且未安装系统 Maven。为避免影响本机其他项目，已在项目目录内准备私有构建工具链：

```text
.tools/jdk21/jdk-21.0.11+10
.tools/apache-maven-3.9.9
.m2/repository
```

后端编译和单元测试统一使用：

```powershell
.\scripts\backend-test.ps1
```

管理后台构建统一使用：

```powershell
.\scripts\admin-build.ps1
```

注意事项：

- 不要求修改系统 `JAVA_HOME`。
- 不要求全局安装 Maven。
- `.tools`、`.m2`、`admin/.npm-cache` 均为本项目本地缓存，不提交到代码仓库。
- Docker daemon 当前未运行时，仍可完成后端编译和单元测试，但 PostgreSQL / Redis 集成测试与 Docker Compose 部署验证需要 Docker 或可用数据库实例。
## 10. 审计日志接口补充

当前测试阶段已提供基础后台操作审计：

```text
GET /api/admin/audit-logs
GET /api/venue/audit-logs
```

说明：

- 平台接口需要平台管理员 token，返回最近 100 条审计日志。
- 场馆接口按当前 token 与 `X-Venue-Id` 做场馆数据隔离。
- 审计字段包括操作类型、对象类型、对象 ID、操作人 ID、角色、场馆 ID、摘要和创建时间。
- 已覆盖场馆入驻、场馆审核、场地创建、场地停用、价格规则保存、订单核销等关键后台操作。



## 11. 开发期 Mock 登录说明

当前测试阶段保留 mock token 登录，便于在没有生产账号体系和微信真实登录态前完成联调：

```text
POST /api/admin/auth/login  admin/admin  -> PLATFORM_ADMIN
POST /api/venue/auth/login  venue/venue  -> VENUE_ADMIN
POST /api/venue/auth/login  staff/staff  -> VENUE_STAFF
POST /api/app/auth/wx-login mock-code    -> APP_USER
```

说明：

- mock token 仅用于测试环境，不等同于生产登录。
- 场馆管理员和场馆员工都必须遵守 `venue_id` 数据隔离。
- 正式上线前仍需补齐真实账号密码、员工管理、菜单权限和微信真实登录态。
