# 场馆预约与球员约战 SaaS 系统最终收尾 Goal 提示词

## Goal

你是一个专业的高级全栈开发工程师。请基于当前仓库、服务器测试环境和 `docs/test-report.md` 的最新记录，继续完成“场馆预约与球员约战 SaaS 系统”的剩余开发、联调、部署、自测和最终测试报告。

本 goal 的目标不是从零重写，而是在现有已经跑通的基础链路上做最终收尾，直到当前阶段达到“P0/P1 核心功能可验收、测试环境可持续演示、上线限制清晰”的状态。

## 本轮必须完成的剩余任务

### 1. 后端业务边界收尾

继续补齐并验证以下边界：

- 支付成功与订单超时关闭的边界测试。
- 已支付订单不能被超时任务关闭的测试。
- 已超时订单不能再被支付成功错误改为已预约的测试。
- 支付成功失败时，支付单状态不能错误变为 `PAID`。
- 普通用户只能访问自己的订单、退款、约战相关数据。
- 场馆管理员不能访问其他场馆的订单、退款、报表、场地、约战数据。
- 已核销订单不能普通取消。
- 退款、约战、报表接口继续检查是否存在跨场馆或跨用户访问风险。

如发现业务代码与测试目标不一致，必须先修正业务逻辑，再补测试。

### 2. 权限与账号体系收尾

当前仍以开发期 mock token 为主，需要完成当前阶段可验收的权限基础：

- 后台登录入口清楚区分平台视角和场馆视角。
- token 中角色、用户 ID、场馆 ID 的使用规则清晰。
- 平台管理员、场馆管理员、场馆员工、普通用户的权限边界可测试。
- 开发/测试 mock 登录必须与未来生产登录明确隔离。
- 如暂不实现真实账号密码、菜单权限、审计日志，必须在最终测试报告中明确列为生产上线前遗留项。

### 3. 管理后台最终完善

管理后台要达到测试人员可操作核心业务的程度：

- 登录页可选择或识别平台/场馆视角。
- 平台总览展示核心统计。
- 场馆审核、场馆详情可操作。
- 场地管理、价格规则管理可操作。
- 预约订单列表、订单详情、核销操作可操作。
- 退款列表、退款详情、处理状态可查看。
- 约战列表、约战详情、成员、AA 支付、AA 退款可查看。
- 基础报表页面按平台/场馆视角展示。
- 页面需要保持清爽、简洁、适合经营后台，不做营销型 landing page。
- 运行构建并部署到 `18201` 后验证首页和 `/api` 代理可访问。

## 完成标准

只有同时满足以下条件，才可以报告 goal 完成：

- 后端 P0/P1 核心业务链路完成并有测试覆盖。
- 支付、退款、订单超时、约战状态边界清楚且测试通过。
- 权限和场馆/用户数据隔离可验证。
- 管理后台可完成核心运营操作。
- 小程序核心用户流程源码层面可走通，结构检查通过。
- 并发预约、Redis 锁场、PostgreSQL 时间槽防重测试通过。
- 报表金额可统计真实订单和退款数据。
- 测试服务器部署成功，未影响其他产品，未使用 80/443。
- `docs/test-report.md` 更新为最终阶段报告。
- 真实微信支付/退款、小程序正式上线条件如未具备，必须被明确列为外部条件或上线前遗留，不可虚假完成。

## 不得虚假完成

以下情况不能报告为已完成：

- 未配置真实微信商户号、API v3 密钥、证书、回调地址，却声称真实微信支付已完成。
- 未配置备案域名和 HTTPS，却声称小程序可正式上线。
- 未使用微信开发者工具或真机测试，却声称小程序真机通过。
- 未执行服务器部署回归，却声称服务器自测通过。
- 只完成页面结构检查，却声称小程序真机链路通过。

## 推荐执行顺序

1. 复核当前代码、文档、测试报告和服务器状态。
2. 补齐支付成功与订单超时关闭边界测试，并修正发现的问题。
3. 检查并补齐用户/场馆数据隔离测试。
4. 完善管理后台剩余操作和展示细节。
5. 完善小程序核心用户路径页面和错误提示。
6. 执行本地后端测试、后台构建、小程序结构检查。
7. 重新部署到测试服务器。
8. 执行服务器健康检查和核心业务冒烟。
9. 更新 `docs/test-report.md` 为最终阶段报告。
10. 给出当前是否达到 P0/P1 验收、是否可正式上线、上线前遗留条件。
