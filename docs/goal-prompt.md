## 产品目标

开发一个面向球馆/体育场馆的 SaaS 系统，同时提供微信小程序给球员使用。

系统服务三类用户：

- 球员用户：查找场馆、订场、支付、退款、发起约战、加入约战、查看订单。
- 场馆商家：管理场馆、场地、营业时间、价格、预约订单、核销、退款、经营数据。
- 平台运营方：审核场馆、管理订单、支付、退款、结算、佣金、账号权限和平台数据。

## 核心业务规则

预约：

- 价格必须由后端计算。
- 用户下单后使用 Redis 临时锁锁定场地。
- 支付成功后必须再次校验冲突。
- 正式预约必须写入 PostgreSQL 时间槽。
- 时间槽按 30 分钟粒度拆分。
- 同一场地同一时间槽只能被一个有效订单占用。

支付：

- 预约订单不设置“已支付”状态。
- 支付状态由 `payment_order` 维护。
- 支付成功后预约订单从 `待支付` 流转为 `已预约`。
- 支付回调必须验签、记录原始日志、幂等处理。
- 正式方案优先使用微信支付服务商模式。
- 如果资质暂不具备，可使用平台普通商户或模拟支付作为开发/测试过渡，但测试报告必须明确标记。

退款：

- 退款金额必须由后端计算。
- 同一支付单不能重复超额退款。
- 未开始且全额退款成功，才释放场地时间槽。
- 部分退款、已核销订单退款、已完成订单售后退款不释放场地。
- 退款回调必须幂等。

约战：

- MVP 约战必须绑定一笔已支付成功的预约订单。
- MVP 不使用 5-10 分钟临时锁长期占用场地。
- P1 再实现 AA 支付、成局、未成局自动退款。
- AA 分摊不改变场馆侧原始预约订单的支付事实。

## 前端要求

微信小程序：

- 采用清爽、可信、运动服务型风格。
- 优先参考 TDesign Mini Program 和 WeUI。
- 必须包含首页、场馆列表、场馆详情、场地预约、订单确认、订单列表、订单详情、退款申请、约战列表、约战详情、创建约战、我的页面。

管理后台：

- 使用 Vue 3 + Element Plus。
- 风格清爽、信息密度适中，适合长期经营使用。
- 必须包含平台后台和场馆后台两个视角。
- 可通过同一后台系统用角色权限区分数据范围。

## 测试要求

必须完成：

- 单元测试
- 接口测试
- 集成测试
- 并发测试
- 权限与数据隔离测试
- 支付回调幂等测试
- 退款幂等测试
- 部署验证

重点测试：

- 10 个用户同时预约同一场地同一时间段，只能成功 1 个。
- 60 分钟订单占用 2 个连续 30 分钟时间槽。
- 90 分钟订单占用 3 个连续 30 分钟时间槽。
- 支付回调重复到达只处理一次。
- 支付成功回调与超时关闭任务并发时，订单最终状态必须正确。
- 退款重复提交不能重复退款。
- 场馆管理员不能访问其他场馆数据。
- 普通用户不能访问他人订单。
