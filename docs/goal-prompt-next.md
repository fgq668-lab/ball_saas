## 本阶段必须完成的后端任务

### 1. 权限与数据隔离

完成生产前可验证的权限基础能力：

- 平台管理员、场馆管理员、场馆员工、普通用户的角色模型。
- 管理后台登录接口和 token 校验。
- 场馆后台接口必须按 `venue_id` 做数据隔离。
- 场馆管理员不能访问其他场馆的场地、订单、退款、报表。
- 普通用户不能访问他人订单。
- 保留开发/测试可用的 mock 登录方式，但必须明确和生产登录隔离。

### 2. 预约与订单完善

完成：

- 订单列表、订单详情接口。
- 取消预约接口。
- 支付超时关闭任务。
- 已支付订单不能被超时任务错误关闭。
- 已核销订单不能普通取消。
- 并发预约同一场地同一时间段只能成功 1 个。

### 3. 支付幂等

在模拟支付流程基础上补齐可测试的幂等模型：

- 支付回调日志落库。
- 同一 `paymentNo` 重复支付成功只处理一次。
- 支付成功后重复回调不能重复写入时间槽。
- 支付成功和超时关闭并发时，订单最终状态必须正确。
- 真实微信支付暂未接入时，测试报告必须明确标记为“模拟支付闭环”。

### 4. 退款完善

完成：

- 用户退款申请接口。
- 后端按规则计算可退金额。
- 超额退款防护。
- 重复退款防护。
- 全额退款且未开始时释放时间槽。
- 部分退款、已核销退款、已完成售后退款不释放时间槽。
- 模拟退款成功和退款回调幂等测试流程。

### 5. 约战 P1 完善

完成：

- 基于已支付预约创建约战。
- 成员加入/退出约战。
- AA 支付单创建。
- AA 支付成功后达到最低人数自动成局。
- 未成局自动取消。
- 未成局自动生成退款记录。
- 约战状态、成员状态、AA 支付状态必须可查询。

### 6. 报表与结算占位

完成可验收的基础报表：

- 平台今日订单数。
- 平台今日交易金额。
- 平台今日退款金额。
- 待处理退款数。
- 场馆数量。
- 场馆维度订单数、交易金额、退款金额。
- 报表必须按场馆隔离，不允许串场。

结算可以仍是占位流程，但必须有清晰数据结构或接口返回说明。

## 执行方式

执行时按以下顺序推进：

1. 复核当前服务器和代码状态。
2. 修复后端缺失功能和业务逻辑。
3. 补齐权限与数据隔离。
4. 补齐支付、退款、约战 P1 幂等和状态流转。
5. 补齐报表统计。
6. 完善管理后台页面和接口联调。
7. 完善小程序页面和接口联调。
8. 补充自动化测试和接口测试。
9. 在服务器重新部署。
10. 执行部署后自测和业务回归。
11. 更新最终测试报告。
12. 只有完成标准全部满足后，才报告 goal 完成。
