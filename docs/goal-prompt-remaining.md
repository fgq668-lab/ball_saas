# 场馆预约与球员约战 SaaS 系统剩余收尾 Goal 提示词

## Goal

你是一个专业的高级全栈开发工程师。请基于当前仓库、服务器测试环境和 `docs/test-report.md` 最新记录，继续完成“场馆预约与球员约战 SaaS 系统”的剩余开发、部署验证、自测和最终测试报告。

本 goal 不是从零重写项目，而是在现有已完成的 P0/P1 主链路基础上做最终收尾。目标是让系统达到“测试环境可持续演示、核心功能可验收、正式上线限制清晰”的状态。

只有完成标准全部满足后，才可以报告 goal 完成。

## 本轮优先完成的剩余任务

### 1. 先做现状复核

必须先确认当前本地代码、服务器部署和测试报告是否一致：

- 检查后端本地测试是否仍全部通过。
- 检查管理后台构建是否仍通过。
- 检查小程序 JSON、JS、页面结构是否仍通过。
- 检查服务器 API 健康状态。
- 检查 `ball-saas-api`、`ball-saas-admin`、`ball-saas-postgres`、`ball-saas-redis` 状态。
- 检查 Flyway 是否已执行到 `V3__audit_log.sql`。
- 如服务器尚未应用最新镜像或 V3 迁移，先部署并验证。

### 2. 审计日志补齐到可验收

当前代码已有审计日志实体、仓库、服务和迁移，但必须完成可验收闭环：

- 确认服务器数据库存在 `audit_log` 表。
- 触发场馆入驻、场馆审核、场地创建、价格规则保存、订单核销等关键操作后，确认审计日志落库。
- 审计日志需记录操作类型、对象类型、对象 ID、操作人 ID、角色、场馆 ID、摘要、创建时间。
- 平台视角可以查看最近审计日志。
- 场馆视角只能查看本场馆审计日志。
- 管理后台如暂不做完整菜单，也至少提供可验证的接口或页面入口。
- 将本地测试、服务器迁移、服务器审计写入结果记录到 `docs/test-report.md`。

### 3. 账号与权限生产前说明

继续保持开发期 mock token 可以用于测试，但必须把生产前限制讲清楚：

- 后台登录入口要清楚区分平台视角和场馆视角。
- token 中角色、用户 ID、场馆 ID 的使用规则要可测试。
- 平台管理员、场馆管理员、场馆员工、普通用户的数据边界要继续保持。
- 如果真实账号密码、员工账号、菜单权限、微信真实登录态仍未完全生产化，必须在最终测试报告中列为“上线前必须完成”，不能写成已正式完成。

### 6. 真实微信支付与上线限制

## 完成标准

只有同时满足以下条件，才可以报告 goal 完成：

- 后端 P0/P1 核心业务链路完成并有测试覆盖。
- 支付、退款、订单超时、约战状态边界清楚且测试通过。
- 权限和场馆/用户数据隔离可验证。
- 审计日志已在服务器落库，并能按平台/场馆视角验证。
- 管理后台可完成核心运营操作。
- 小程序核心用户流程源码层面可走通，结构检查通过。
- 并发预约、Redis 锁场、PostgreSQL 时间槽防重测试通过。
- 报表金额可统计真实订单和退款数据。
- 测试服务器部署成功，未影响其他产品，未使用 80/443。
- `docs/test-report.md` 更新为最终阶段报告。
- 真实微信支付/退款、小程序正式上线条件如未具备，必须被明确列为外部条件或上线前遗留，不可虚假完成。

## 不得虚假完成

以下情况不能报告为已完成：

- 未配置真实微信商户号、API v3 密钥、证书、回调地址，却声称真实微信支付已完成。
- 未配置备案域名和 HTTPS，却声称小程序可正式上线。
- 未使用微信开发者工具或真机测试，却声称小程序真机通过。
- 未执行服务器部署回归，却声称服务器自测通过。
- 只完成页面结构检查，却声称小程序真机链路通过。

## 推荐执行顺序

1. 复核当前代码、文档、测试报告和服务器状态。
2. 确认 Flyway V3 和审计日志是否已在服务器生效。
3. 补齐审计日志查询接口或后台入口，并验证平台/场馆隔离。
4. 执行后端本地测试、后台构建、小程序结构检查。
5. 部署最新后端和后台到测试服务器。
6. 执行服务器健康检查、核心业务冒烟、约战回归、审计日志落库验证。
7. 回归管理后台核心页面和 `/api` 代理。
8. 更新 `docs/test-report.md` 为最终阶段报告。
9. 给出当前是否达到 P0/P1 验收、是否可正式上线、上线前遗留条件。
